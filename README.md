# 十三支・鬼牌五條版（Thirteen Poker）

可以直接在瀏覽器玩的十三支（Chinese Poker）：

- **2 / 3 / 4 人**，**人數 = 牌副數**（4 人就是 4 副牌），每副牌多 2 張**鬼牌（百搭，可當任何牌）**。
- 多副牌 + 鬼牌 → 會有**五條**（5 張同點數，比同花順還大）。
- 電腦對手三級：**困難 / 超困難 / 極限**。
- 純靜態網頁（HTML + JS，無依賴、無後端），手機也能玩。

## 玩

**線上直接玩：<https://chchiuleroy.github.io/thirteen-poker/>**

本機：

```bash
# 直接用瀏覽器開 index.html 即可，或：
python -m http.server 8000     # 然後開 http://localhost:8000
```

操作：在手牌上**點選多張**（或按住滑鼠／手指在牌上**拖曳劃選**），再按上方的「放入頭墩／中墩／尾墩」，一次放好；已放的牌也能再選來換墩或「收回手牌」。全部放好且不倒水後按「攤牌」；「提示擺法」會用極限 AI 幫你擺一組。

規則（含計分表、與傳統玩法的差異）見 [docs/RULES.md](docs/RULES.md)。要點：

- 牌型：五條 ＞ 同花順 ＞ 鐵支 ＞ 葫蘆 ＞ 同花 ＞ 順子 ＞ 三條 ＞ 兩對 ＞ 一對 ＞ 烏龍；尾 ≥ 中 ≥ 頭，否則倒水。
- 計分：每墩 ±1；打槍（三墩全勝）6 分；全壘打（打槍所有人，需 ≥3 人）每人 12 分；頭墩三條、中墩葫蘆／鐵支／同花順／五條、尾墩鐵支／同花順／五條有額外加分。
- **沒有實作**傳統的報到牌型（一條龍、三同花、六對半…）與莊家／賠率制。

## 電腦難度

| 難度 | 做法 |
|---|---|
| 困難 | 加權牌型分數最大化（頭／中／尾權重、點數權重由模擬校準） |
| 超困難 | 對「對手牌墩分布」最大化期望得分（含打槍、額外加分）；分布表由自我對弈（虛擬對局）迭代到穩定（相鄰兩輪各墩分布的 KS 距離 ≤ 0.004、新舊表對戰得分趨近 0；這是經驗上的穩定，不是均衡或不可剝削性的證明） |
| 極限 | 超困難 ＋ 全壘打期望（自己全壘打的收益、被全壘打的損失，都是近似）＋ **逐局學習每位玩家（包括你）的牌墩分布**（貝式收縮到先驗），越玩越針對你 |

電腦只看自己的 13 張牌與牌堆組成，不偷看任何人的手牌；極限學習用的只有攤牌後的公開牌墩。

### 實測強度（模擬結果，非保證）

`duplicate` 對戰：同一批牌讓每個座位各打一遍，扣掉運氣。數字是「每手平均得分 ± 95% 信賴區間」，所有 AI 在全部模擬中**倒水 0 次**。完整輸出：[docs/tournament_output.txt](docs/tournament_output.txt)。

| 對戰（2 人桌） | 副牌數 | 結果 |
|---|---|---|
| 貪心（基準）vs 隨機（基準） | 6000 | +3.000 ±0.050 |
| 困難 vs 隨機 | 6000 | +5.367 ±0.044 |
| 超困難 vs 隨機 | 6000 | +5.797 ±0.039 |
| **超困難 vs 困難** | 6000 | **+0.261 ±0.030** |
| 極限（第一局）vs 困難 | 3000 | +0.239 ±0.042 |
| 極限（第一局）vs 超困難 | 3000 | 0（兩者第一局擺法相同，見下） |

4 人桌 `[極限, 超困難, 困難, 貪心]`：+1.700 ±0.105／+1.688 ±0.090／+0.848 ±0.098／−4.237 ±0.124（1500 副牌）。

**「極限」比「超困難」強在哪——要講清楚：**

- 超困難已經近似「對一群均衡打法對手」的最佳擺法。2 人桌第一局，極限和超困難擺法**完全一樣**；多人桌極限只多全壘打期望項，4 人桌對三個超困難 +0.058 ±0.043（1500 副牌，不顯著；另外跑 4000 副的探針是 +0.046 ±0.024，見 HL_LOG）。
- 極限的優勢來自**學習對手的習慣**。連續多局實驗（配對差值，400 場 × 60 局，[docs/sessions_output.txt](docs/sessions_output.txt)）：極限 − 超困難 的每手得分差：

| 對手 | 第 2–5 局 | 第 16–30 局 | 第 31–60 局 |
|---|---|---|---|
| 貪心（2 人） | +0.01 ±0.03 | +0.16 ±0.03 | **+0.25 ±0.03** |
| 困難（2 人） | −0.03 ±0.03 | +0.04 ±0.02 | +0.03 ±0.02 |
| 困難 ×3（4 人） | +0.07 ±0.08 | +0.16 ±0.06 | **+0.19 ±0.05** |
| 超困難（2 人） | −0.04 ±0.03 | −0.02 ±0.02 | −0.01 ±0.02 |

  在這幾個測過的對手中：對貪心賺最多、對困難次之、對超困難不賺不虧。實驗沒有量化「固定偏好」的程度，所以只能說「對這幾種固定策略如此」，不能推廣成「越固定越好賺」的一般規律；人類玩家是否可被剝削、剝削多少，**這裡沒有真人數據**，是未驗證的。

## HL（Heuristic Learning）

AI 策略就是程式碼（`js/ai.js`），用模擬回饋改它、舊行為用測試固化，沒有梯度。每一輪實際做了什麼、哪些路走不通、哪些數字，見 [docs/HL_LOG.md](docs/HL_LOG.md)。

## 專案結構

```
index.html, css/, js/app.js     網頁介面
js/engine.js                    規則引擎（牌墩評價、計分、發牌）— 瀏覽器與 Node 共用
js/ai.js                        四種策略（random/greedy 只當基準；hard/super/extreme 開放）
js/tables.js                    自動產生的對手牌墩分布表（sim/calibrate.js）
sim/                            校準、對戰、連續多局、交叉驗證（Node + Python）
tests/                          單元測試
docs/                           規則、HL 紀錄、完整模擬輸出
```

## 已知限制

- 極限的全壘打期望是近似：假設三墩獨立，且「對手同時打槍其餘玩家」用固定機率 0.11。
- 沒有報到牌型與莊家制；五條的額外加分（中墩 +5、尾墩 +4）是本專案自訂，傳統規則沒有統一數字。
- 超困難的期望得分假設三墩的對手牌力互相獨立（實際有相關），蒙地卡羅檢驗沒看到可利用的差距，但不是證明。
- 「困難」的權重是對自己調校的，沒有針對人類。
- 強度數字都是 AI 對 AI 的模擬；沒有人類對局數據。
